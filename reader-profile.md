# Reader profile

**The cross-book ledger.** The detail is not here — it lives one file per book at
`context/books/<domain>/<cluster>/<book>.md`, and only ever records what this system produced.

**Maintained by Claude Code.** He can edit it directly and sometimes will; most updates happen
because he asked for one, or because something was read and the record is behind.

> **Never write a cell you did not read in a file or hear from him this session. Ask, then write.
> An unasked cell stays empty.**
>
> An empty cell is a known gap. A guessed one is indistinguishable from a real answer. **`Effort` is
> the sharp case:** it is measured minutes, and copying the estimate into it writes 30 = 30 and
> destroys the only signal that says whether the schedule is calibrated.

## Chapter ledger

One row per chapter. **`Read` ticks only when both hold:** the recall was written closed-book
*before* the explanation layer, **and** `## Open questions` was filled in by hand.

**Effort against estimate is the most useful column here** — the only honest signal of whether an
estimate was any good. 120-against-85 is data, not a failure, and since there is no length budget
(`context/reader.md` §2) it is *only* data: there is no schedule for it to have broken.

**`Effort` is obtainable, not estimated.** He told us on 2026-08-31: *"Yes I track how much I read in
time tracker."* So `/progress` **asks him to read the number off**, and never pre-fills it from the
estimate — copying the estimate writes 30 = 30 and destroys the only comparison this column exists
to make.

## The honesty valve

**If three books in a row say "reading it plainly would have been faster", the system is wrong and
needs changing — not more effort.**

Nothing else in this repository overrides that sentence, and no amount of work already done makes it
untrue.
